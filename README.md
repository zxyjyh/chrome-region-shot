# Region Shot · 区域截图

一个 Chrome 扩展：在网页上框选起始位置和宽度，滚动到结束位置确认，截取这一整块内容（可以跨越多屏），保存为 PNG。

## 安装

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录
4. 把扩展图标固定到工具栏（可选）

## 使用（两段式，对触摸板友好）

1. 在普通网页上点击扩展图标，或按 `Alt+Shift+S`
2. **第一步：拖拽**确定起点和范围（拖到视口四边会自动滚动）
3. 松开后进入第二步：**两指滚动**到想结束的位置，选区框会随滚动延伸——上下滚就纵向延伸，左右滚就横向延伸
4. 点选区右下角的 **「✓ 完成截图」**（或点页面任意位置）——按钮会跟着选区走，滚远了也点得到
5. 角标显示进度百分比，结束显示 `OK`，失败显示 `!`
6. 截图完成后会打开 **标注编辑器**：把图片拉到想标的位置，加文字 / 箭头 / 矩形，可拖动、改颜色和字号、`⌘Z` 撤销
7. 点右上角 **「✓ 保存 PNG」** 下载；点「取消」或直接关标签页则不保存
8. 框选阶段按 `Esc` 或点右键取消

> 为什么分两步：Mac 触摸板上「按住拖拽」和「两指滚动」没法同时做，所以把定起点和定终点拆开。

## 工作原理

1. **先附加调试器，再框选**：`chrome.debugger` 会让 Chrome 显示调试提示条，视口高度会变化约 56px。先框选再附加会导致选区尺寸和实际截图对不上。
2. **探测真正在滚动的东西**，共三种：
   - 整个页面（`document.scrollingElement`）
   - 视口中心向上找的第一个 `overflow: auto/scroll` 且内容溢出的祖先容器（大量 SPA 的主内容区）
   - **同源 iframe 内部的滚动容器**（很多文档站把正文整个塞进 `srcdoc` iframe，外层页面本身完全不滚）
3. **坐标统一用该滚动容器的内容坐标**，所以滚动不会让选框错位。
4. **截图由扩展自己控制滚动**：从起点开始一屏一屏滚过去（先横向铺完一行，再纵向推进），每屏用 CDP `Page.captureScreenshot` 截一次，在 background 里用 `OffscreenCanvas` 拼接。选区比视口宽时同样能截全。
5. 每屏能截多宽/多高取决于当下真实的视口尺寸，所以按「实际截到的尺寸」推进，而不是预计算分段——避免视口变化导致漏内容。
6. 拼好的图不直接下载，而是写进 IndexedDB 并打开 `editor.html`（扩展页面），由用户在图上标注后点保存；编辑器打不开时自动退回直接下载原图。
7. 保存优先用 `downloads.download`（blob URL → data URL），都失败时退回页面内 `<a download>`。

**请从真正的内容区内部开始拖拽**（iframe 页面就从正文区域开始），扩展会跟随那个区域所属的滚动容器。从页头/边框处开始框选时，拿不到可滚动目标，只能截一屏。

### 为什么不用 `captureBeyondViewport`

CDP 的 `Page.captureScreenshot` 支持 `captureBeyondViewport: true` 一次性渲染视口外内容，看起来更省事。但它依赖「文档坐标 + 文档高度」，遇到内部滚动容器时：

- `window.scrollY` 恒为 0
- `document.scrollingElement.scrollHeight` 等于一屏高度

结果是算不出真实范围，只能截到当前可见区域。改成主动滚动后，两种页面结构走同一条路径。

## 权限说明

| 权限 | 用途 |
|---|---|
| `activeTab` | 只在你点击扩展时，临时获得当前标签页的访问权 |
| `scripting` | 注入框选界面、控制滚动 |
| `downloads` | 保存截图文件 |
| `debugger` | 调用 CDP 截图。**截图期间浏览器顶部会出现「正在调试此浏览器」黄条**，结束后自动消失 |

## 已知限制

- 截图期间页面会被程序滚动（会看到画面上下移动），这是滚动拼接的固有行为
- 截图期间顶部会出现调试提示条
- 只跟随一个滚动容器：跨不同滚动容器（比如从页头开始、一直截到 iframe 正文）不保证正确
- 跨域 iframe 无法访问内部，退化成只能截一屏
- 位置固定 / `position: sticky` 的元素会在截图期间被临时隐藏，不会在长图里重复出现（代价是长图里看不到固定导航栏）
- 懒加载内容：滚到底才加载的，可能在截图时还没准备好
- 长图宽高都限制在约 30000 设备像素内，超出部分会被截断
- 如果该标签页开着 DevTools，扩展无法附加调试器，会显示 `!`
- `chrome://` 开头的页面、Chrome 应用商店、其他扩展页面无法截图
- 横向滚动依赖页面本身能横向滚动：`overflow-x: hidden` 或内容不比视口宽的页面，超出的右侧部分截不到

## 自测

项目自带端到端测试：真实加载扩展到 Chrome，用 CDP 发真实鼠标事件走完整交互，最后解码 PNG 检查像素内容。

```bash
node test/e2e.js            # dpr = 1
node test/e2e.js --dpr 2    # Retina
```
覆盖四种页面结构（内部容器滚动 / `window` 滚动 / 同源 iframe / 横向+纵向双向滚动），断言：

- 松手后不会自动开始截图（按钮仍在）
- 滚动后选框会延伸
- 产出的图像尺寸 = 选区宽度 × 高度 × dpr
- 图像从上到下的颜色序列与页面内容一致（说明截到了正确的区间，而不是当前视口）
- 双向滚动页面上，横向和纵向都翻过视口后，图像尺寸与选区一致，且四个象限的颜色对得上（说明二维拼接没有接错位置）
- 标注（文字、箭头）出现在导出图的正确位置
- 第二阶段拖动页面不会被误判成「点任意位置确认」；点击右侧滚动条区域也不确认

另有一个**第二阶段交互检查**（headful），专门盯框选之后的滚动与拖动：

```bash
npm run test:phase2
```

它验证：滚轮能滚、选区跟着延伸、按钮贴着选区右下角、拖动页面不确认、拖动后还能继续滚、原地点击能确认并打开编辑器。

另有**真实窗口视觉检查**（headful，会把 Chrome 窗口弹出来）：

```bash
npm run test:visual
```

它用 `test/pages/demo-article.html` 走一遍「框选 → 滚动 → 标注 → 保存」，把每一步的界面截图存到 `test/shots/manual/`，并断言：多行文字、矩形、拖动、撤销、选中文字改字号、吸顶导航不被拍进长图、保存后编辑器自动关闭。

商店展示图由同一套流程抓素材后合成：

```bash
npm run store:shots     # 输出 store-assets/screenshot-1..3.png（1280×800）
```

依赖 Node 18+、`ws` 模块（全局安装也行）、Chrome。

## 图标

源文件是矢量图，在 `icons/` 下：

| 文件 | 用途 |
|---|---|
| `icon-full.svg` | 128 / 48 px |
| `icon-32.svg` | 32 px 专用（线更粗、元素更少） |
| `icon-16.svg` | 16 px 专用（只保留箭头和一条上边界） |

**为什么小尺寸不直接缩放**：128px 的角标框缩到 16px 时线宽只剩约 1px，会和背景糊成一团。所以 16/32 单独画了简化版。`icons/preview-sizes.png` 是两套方案在 128/48/32/16 下的对比图。

重新生成 PNG：

```bash
npm run icons
```

脚本会断言输出必须是 RGBA——否则圆角外侧会变成白色方块。

> 踩过的坑：`--default-background-color=00000000` 这个常见的"透明截图"启动参数在 Chrome 157 的 headless 下会让**页面 target 完全不出现**（`/json/list` 里只剩 service_worker），导致脚本连不上页面。正确做法是去掉该参数，改用 CDP 的 `Emulation.setDefaultBackgroundColorOverride` 配合 `omitBackground: true`。

## 打包上架

```bash
npm run pack
```

产物在 `dist/region-shot-<version>.zip`。文件清单从 manifest 反推，`test/`、`scripts/`、`*.md` 不会被打进去。详细的上架流程见 `PUBLISHING.md`，表单文案见 `store-listing.md`。
